## Model and derivation

Use the requested standard embedding, with both coordinates periodic in radians:

```
A(v) = R + r cos(v),  R > r > 0
X(u,v) = (A cos(u), A sin(u), r sin(v))
X_u = (-A sin(u), A cos(u), 0)
X_v = (-r sin(v) cos(u), -r sin(v) sin(u), r cos(v))
g_uu = A², g_uv = 0, g_vv = r²
```

The affine-time kinetic Lagrangian is L = (A² u̇² + r² v̇²)/2. Since u is cyclic,
`d(A² u̇)/dt = 0`. Since `A_v = -r sin(v)`, expanding gives:

```
ü = (2 r sin(v) / A) u̇ v̇
v̈ = -(A sin(v) / r) u̇²
```

Equivalently the only nonzero Christoffel symbols are:

```
Γᵘ_uv = Γᵘ_vu = -r sin(v)/A
Γᵛ_uu = A sin(v)/r
```

The second equation follows from `r² v̈ = ∂L/∂v = -A r sin(v) u̇²`.
Continuous geodesics conserve squared speed `s² = A² u̇² + r² v̇²` and cyclic momentum
`p_u = A² u̇`. The integrator does not conserve either exactly; both are measured below.

An orthonormal tangent frame is `e_u = X_u/A`, `e_v = X_v/r`. For initial speed s and
angle α measured from +e_u toward +e_v:

```
u̇₀ = s cos(α)/A(v₀)
v̇₀ = s sin(α)/r
```

Thus initial surface speed is s for every launch location, rather than depending on the
coordinate scale. Controls use degrees for u₀, v₀ and α; internal values are radians. Distances
are dimensionless world units, and time is simulation seconds. No force, steering, randomness,
projection back to the surface, or velocity renormalization is used.

The existing accepted M2 torus is Y-up: display maps standard `(x,y,z)` to `(x,z,y)`.
This fixed orthogonal coordinate permutation (an isometry with orientation reversal) exactly
matches M2's mesh and camera convention; it does not change the metric or solver equations.
Particle centers and trail samples come from this analytic parameterization. Rendered straight
trail segments are polyline approximations between samples; they are not exact curved arcs.

## Numerical method and safety

`WorkspaceCore/TorusGeodesic.swift` contains the CPU Double reference/runtime solver, independent
of SwiftUI and Metal. State is `(u,v,u̇,v̇)`. Classical four-stage RK4 uses fixed `dt=1/240 s`.
The test-only/public integration entry permits other positive steps ≤0.1 s for convergence
checks; the app always uses 1/240. Wrap u/v into [-π,π) only after a full RK4 step, with
velocities unchanged. Stage trigonometry is periodic; a wrapped seam is never a world-space jump.

Exact v=0 and v=±π use the analytic `sin(v)=0`, including at RK4 stages, instead of introducing
a spurious residual from floating-point sin(π). Exact cardinal launch angles use the same helper.
There is **no epsilon neighborhood snapping**; a nearby inner-equator launch evolves away and
has its own regression test. The inner equator is transversely unstable, so preserving its exact
analytic invariant is distinct from damping a perturbed trajectory onto it.

Supported app ranges match M2: R=4…9, r=0.5…3; hence R-r≥1 and the chart stays nonsingular.
Speed=0.25…8 units/s, u₀/v₀=0…360°, α=-180…180°. Reject non-finite/out-of-range configuration,
nonpositive/invalid test dt, invalid step counts and trail capacity before integration/allocation.
If a next state is non-finite or relative speed drift reaches 2%, stop and expose an error;
never recover by silently changing speed or adding a random launch. Restart restores the known
initial state. The 2% guard is a failure boundary, not a reported accuracy tolerance.

Fixed-step playback reuses the existing clock: clamp a wall gap at 0.25 s, execute at most
64 steps per drawable, discard excess time and report it. The unchanged timestep constant now
belongs to `FixedStepClock`; Lorenz aliases it and all existing clock/math tests still pass.
Pause consumes no simulation time. Renderer anchors clear on pause/restart, observed minimized
windows and absent drawables, avoiding catch-up across those events. On an unobserved long gap,
the same cap/drop policy applies. Single-step integrates one dt only when paused; Restart clears
clock/steps/history while preserving pause and camera. No FPS-as-dt or quality-dependent solver.
Deterministic replay means same configuration, dt, executable/hardware/precision assumptions;
bit-identical results across architectures or compilers are not promised.

## Architecture and rendering

- `WorkspaceCore/TorusGeodesic.swift`: metric/embedding, RK4 reference, fixed-step playback and
  fixed-capacity CPU ring. Tests operate directly on this code, not on UI callbacks.
- `CreativeMath/GeodesicSession.swift`: observable edit state wrapping the existing Torus
  `SurfaceSession`; mutable per-frame playback is observation-ignored to avoid full UI updates
  on every step. `GeodesicInspector.swift` contains native controls and the actual gallery preview.
- `SurfaceViewport.swift`: existing surface renderer/camera adapter gains an optional geodesic.
  M2-only views retain on-demand drawing. Geodesic views request 60 Hz and fixed-step CPU updates;
  achieved rate is not claimed. No duplicate torus scene renderer or GPU single-particle solver.
- `SurfaceMetal/GeodesicTrails.swift`: thin antialiased amber screen-space line quads and a
  small round particle marker. The marker center is the exact sampled surface point, with a
  constant-pixel billboard footprint rather than a physical sphere. Colors distinguish motion
  from the accepted cool surface grid; no glow or decorative effects.
- Reuse M2 surface depth by explicitly storing/loading it between the surface and overlay passes.
  Overlay tests depth, writes no depth, and uses a small raster-only bias against faceting/z-fighting.
  Back-side motion should be occluded; device tests and visual review still required. Near-plane
  and degenerate line segments are rejected whole. Lines join mapped world positions across seams.
- Three persistent 8192×float4 upload buffers rotate under the shared three-in-flight semaphore
  and serial queue. CPU ring data is copied to the free slot; no Metal buffer allocation/readback
  or blocking GPU wait per frame. Unchanged mesh/radii are cached by the M2 renderer. Radii edits
  rebuild the mesh; launch/appearance/camera/ordinary motion do not.
- CPU ring capacity is 128 KiB; three GPU uploads total 384 KiB. These are source-derived trail
  budgets, excluding arrays/solver/UI/mesh/depth/drawables/driver overhead, not process memory.
  At maximum capacity and 60 draws/s, a full-ring upload is 7.5 MiB/s of copied sample data.
  This is a calculated traffic budget, not measured performance. No framework/optimization engine.

|---|---:|---:|---:|

Constraint is `(hypot(x_display,z_display)-R)^2 + y_display^2 - r^2`; table shows max absolute
residual in squared world units. Positions remain on the analytic surface by construction;
small residuals are arithmetic roundoff, not an independent physical constraint integrator.
Speed/momentum tests require relative error <1e-7 over these runs and the supported corner tests,
providing margin over the observed results without asserting exact conservation. Constraint
threshold 1e-11 accommodates Double trig/subtraction roundoff at world scales up to 12.

outer 2.69121e-12; inner 6.59732e-12. Limit 1e-9 leaves margin for accumulated Double angular
roundoff while still testing actual multi-lap geometry, not just the zero acceleration at t=0.
