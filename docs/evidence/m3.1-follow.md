# M3.1 continuous particle following

Implemented at user request; M3.1 remains unaccepted pending actual Mac animation review.
This replaces the prior one-time Focus particle action. M3.2/M3.3 were not started.

## Behavior and files

- `WorkspaceCore/CameraProjection.swift`: small testable `ParticleCameraTracking` policy.
  Follow mode resolves target=current particle position; yaw/pitch/distance stay unchanged.
  Enabling clears pre-existing pan to center the particle. Panning afterward adjusts framing.
  Disabling freezes the current target, avoiding a jump back to the pre-follow target.
- `CreativeMath/GeodesicSession.swift`: follow toggle state, frame-camera resolution and shared
  reset; restart/configuration edits preserve follow mode, while Camera/Restore Defaults disable
  it. No solver change, velocity adjustment, wall-time accumulation or auto normal rotation.
- `GeodesicInspector.swift` replaces Focus with a native Follow particle toggle.
  `CreativeMathApp.swift` routes ⌘0 through the same geodesic reset as the Camera button.
- `SurfaceViewport.swift` computes one camera after integration and uses it for both surface
  and trail/particle rendering. Base camera state is not rewritten every frame. A separate
  snapshot observed only by `GeodesicAxisLabels` keeps coordinate labels aligned; it updates
  only when the coordinate grid is visible. `WorkspaceView.swift` uses that small child.
- Existing camera/Metal test file adds two host tests; UI test checks toggle, step and both
  reset routes, with a screenshot attachment. No new package/target/dependency or solver engine.

Depth occlusion remains active. Fixed viewing orientation can leave the particle behind the
surface; orbit/zoom to inspect it. Close following may intersect the torus depending on framing;
no collision-avoidance system is claimed. The mode does not automatically zoom in or keep the
particle's normal aligned with the camera. These choices preserve the user's viewing control.

   stable chosen yaw/pitch/zoom. Try 1×/2×/4×, orbit, zoom and pan. There should be no automatic
   normal-driven camera roll/rotation or solver restart when the toggle changes.
