## Disappearing trajectories: findings and limits

The original observation has no recorded parameter set or GPU capture, so its exact cause
cannot be established in this session. The following separates demonstrable behavior from
remaining hypotheses:

| Candidate | Finding |
|---|---|
| Stable equilibrium | Demonstrated on the Double reference for sigma=10, beta=8/3, rho=0, 0.5 and 10, over 100 simulation units. Both symmetric nonzero basins tested. Endpoint and derivative errors <1e-8; no reference recovery resets. |
| Trail aging | Age uses integer distance behind the head times dt, not wall time. At equilibrium old moving samples fade/evict while newly recorded segments become arbitrarily short. Pause freezes this age. CPU boundary tests pass; actual paused raster test remains GPU-skipped. |
| Degenerate geometry | Line shader omits projected segments shorter than 0.0001 pixel-scale direction units; ribbon shader omits squared world lengths <1e-12. Exact/near equilibria therefore have no lasting visible path. These guards prevent invalid normalization, rather than force motion. |
| Camera framing | Model is displayed as (x,z,-y)-(0,25,0); camera does not automatically recenter or rescale on model edits. Convergence can move the subject away from the default butterfly center. Zoom/pan can also hide it; Reset Camera restores the preset pose. Projection unit tests pass; desktop framing is unverified. |
| Non-finite states | RK4 next state is checked for finiteness and absolute coordinates >=10000; recovery resets only that path to its deterministic initial point and count=1/head=0, discarding connections to old samples. Safe math compilation is requested. Existing GPU fault-injection test is skipped here. |
| Ring/state bugs | Source indexing is consistent: oldest=(head+capacity+1-count)%capacity; render reads only valid samples. Existing wrap test and new actual-history checks are provided, but no GPU execution means no runtime clearance of this hypothesis. |

The Lorenz origin is an equilibrium at every parameter setting. For positive sigma and beta,
rho<1 gives an attracting origin. For rho>1 there are equilibria
(±sqrt(beta*(rho-1)), ±sqrt(beta*(rho-1)), rho-1). At sigma=10, beta=8/3,
rho=10 these are attracting (the linear stability boundary is about 24.74).
These statements describe local stability, not a guarantee of any arbitrary trajectory's
transient duration or basin. Tests use actual integrated trajectories from specified starts.

The z axis is invariant: x=y=0 implies z(t)=z(0)*exp(-beta*t), even after changing rho
back to 28. Finite-precision trajectories may also reach a stationary representable point
near an equilibrium. Merely restoring chaotic parameters need not revive a path at the
exact origin; **Restart** supplies the original nonzero seeded initial condition honestly.
There is no jitter, forced-chaos injection, hidden dt change, or automatic reseeding of finite
convergent states.

A runtime “settled” badge was considered but deferred: stable parameters alone do not prove
that current GPU trajectories have settled. Accurate state classification would require new
GPU diagnostics/readback and validation unavailable here. The small static explanation is
honest without pretending to observe the live state.

## Pipeline and resource audit

- Metal and CPU implement the same four RK4 stages. Runtime Float32 dt/model arithmetic is
  compared with Double over 240 steps (tolerance 0.005) by the existing device test and CLI.
  Long-horizon chaotic equality is deliberately not asserted. GPU parity **NOT RUN** here.
- dt=1/240, speed affects the number of steps only. Wall gaps clamp at 0.25 seconds,
  dispatch budget is 64 runtime steps, excess time is discarded. Refresh-independent,
  pause, fractional-phase and dropped-time host tests pass. Renderer clears wall-time anchors
  on pause changes, observed absent/minimized windows and reset.
- Seeded initialization matches the CPU integer hash. Restart uses current configuration,
  rebuilds 2400+trailLength-1 real RK4 steps and preserves camera/pause. Restore Preset
  Defaults additionally restores controls/speed/camera. Model edits retain positions and
  expose only one history point; topology/seed/representation changes rebuild history.
- Ribbons transport the frame using derivatives in display coordinates; packed sides are
  finite 24-bit integers in float4.w. Zero/non-finite and antiparallel tangent fallbacks,
  quantization and a 3000-step packed transport test pass on CPU. Shared endpoints avoid
  miter division. Whole-segment near-plane rejection is present. Raster validation pending.
- Private state/history buffers are persistent. Topology changes allocate new buffers;
  ordinary parameter/camera/fade/width edits do not. Command buffers retain encoded resources;
  default tracked hazards, one serial command queue and buffer barriers order compute/render.
  Three in-flight commands are bounded by a nonblocking semaphore in the app.
- No CPU history construction, per-frame readback, buffer allocation, or per-frame GPU wait
  is present in the app path. Validation-only readback uses staging buffers and waits.
  Pipeline states are created per viewport, not per frame. One instanced trail draw per frame.
  Source audit cannot replace Metal API/Shader Validation or a GPU capture.

## Performance: source budgets, not measurements

Default scene counts, calculated from current settings (16 history bytes/sample, 32 state
bytes/path; six vertices/segment; one instanced draw):

| Preset | History bytes | State bytes | Visible segments/path | Submitted vertices/frame |
|---|---:|---:|---:|---:|
| Classic | 393216 | 384 | 1681 | 121032 |
| Filament | 1179648 | 768 | 2401 | 345744 |
| Sculpture | 393216 | 192 | 2881 | 103716 |

Maximum supported history is 16 MiB (128*8192*16), plus 4096 state bytes. This excludes
textures, drawables, pipelines, driver allocations, SwiftUI and retained old resources during
reconfiguration; it is **not process memory**. Sculpture adds frame transport, neighboring
history reads and lit fragments. Relative line/ribbon cost cannot be inferred from vertex
counts alone. GPU buffer allocations, CPU frame overhead, compute/render timings, memory,
thermal behavior and sustained FPS are **NOT MEASURED**. No 60 FPS or 1 GB compliance claim.

## Exact local checks still required

From a normal desktop Terminal on the target M2 Air, first run:

```sh
./scripts/test.sh
xcodebuild -project CreativeMath.xcodeproj -scheme CreativeMath \
  -destination 'platform=macOS' test
TMPDIR=/private/tmp/ ./scripts/build-app.sh release
open '/private/tmp/creative-math-build/Creative Math.app'
```

Require **zero GPU skips**, no command failures, actual raster/parity/ring/recovery test passes.
In Xcode enable Metal API Validation and Shader Validation for the correctness run; turn them
off for performance. A failing GPU test or runtime shader compilation is unresolved work.

Manual acceptance checks (record screenshots at 1440x900 and 1280x800 pt, plus compact
900x600 and minimum inspector size):

1. Check all three presets, Retina resizing, clean canvas, snapped/unsnapped inspector, focus,
   invalid fields and footer. Read every explanation while scrolling; verify no clipping.
   Drag/resize/restore the inspector; test keyboard focus, Escape and VoiceOver labels.
2. Enter nan, inf and out-of-range model values; confirm error and unchanged committed model.
   Escape restores the value. Try fractional trajectory/history counts (reject), valid typed
   counts (accept), and continuous model sliders versus deferred topology sliders (commit
   on release). Switch presets after a dirty/invalid focused edit to check event ordering.
3. Pause Classic. Change sigma to 12, pan/orbit/zoom, Restart: retain sigma/camera/pause and
   rebuild identical paths. Restore Preset Defaults: sigma=10, speed=1, camera reset, still
   paused. Cycle Classic/Filament/Sculpture repeatedly; verify counts and Ribbon Width context.
4. sigma=10, beta=2.6666666667, rho=0.5; Restart, run at speed 4 for 25 seconds. Expect
   convergence/shrinking trails, not persistent chaos. Repeat rho=10 (nonzero equilibrium),
   then Restore Preset Defaults + Restart (butterfly returns). Do not require chaotic revival
   merely by editing rho when already at the exact origin.
5. Pause each preset, wait 10 seconds, orbit and redraw: no trail aging. Set Fade Delay/Duration
   to 0, separately and together, and to 30; step once. Reduce trail points to 256: only the
   retained history is visible, no stale connections after model edits or ring wrap.
6. Sculpture: orbit near edge-on directions, zoom and pan through near-plane intersections;
   test ribbon width 0.04 and 1.2, settled paths and rapid model edits. No spikes/non-finite
   geometry. Test background/foreground and minimize/resume without unbounded catch-up.
