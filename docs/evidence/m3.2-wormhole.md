## Spatial model and assumptions

This is the equatorial **spatial** section of the Ellis geometry. It is not a photon model,
relativistic lensing or a full spacetime simulation. Signed proper radius l traverses both
regions through l=0; φ is periodic. Distances/affine parameter s use dimensionless world units.

```
g_ll = 1, g_φφ = l²+a², g_lφ = 0, a > 0
r(l) = hypot(l,a), z(l) = a asinh(l/a)
X(l,φ) = (r cos φ, r sin φ, z)
```

Since r'=l/r and z'=a/r, |X_l|²=(l²+a²)/r²=1, |X_φ|²=r² and X_l·X_φ=0:
the embedding induces the stated metric, smoothly including l=0. Display permutes (x,y,z)
to (x,z,y), matching the accepted Y-up camera convention. The outward display normal is
`(a cos φ, -l, a sin φ)/r`. Neither side is a disconnected funnel; the mesh shares one throat row.

From `L=(l'²+(l²+a²)φ'²)/2`, Euler–Lagrange gives:

```
l'' = l φ'²
φ'' = -2 l l' φ'/(l²+a²)
E = l'² + (l²+a²)φ'² = 1              (unit squared speed)
J = (l²+a²)φ'                        (cyclic momentum)
```

The nonzero Christoffel symbols are Γˡ_φφ=-l and Γφ_lφ=Γφ_φl=l/(l²+a²).
Combining the invariants yields `l'² = (l²+a²-J²)/(l²+a²)`. Thus |J|<a crosses,
|J|>a has a turning point at `|l_turn|=sqrt(J²-a²)`, and |J|=a is critical. The exact
throat circle is also valid initial data. No bounce logic or hand-authored turn is implemented.

Launch controls specify l₀, φ₀ and b=J/a. Set φ'₀=J/(l₀²+a²) and l'₀ toward the throat
with magnitude sqrt(1-J²/(l₀²+a²)); at l₀=0 the chosen radial direction is negative l.
Invalid |J|>sqrt(l₀²+a²) is rejected and reported, never clamped into a valid launch. The max(0,…)
in initialization handles only arithmetic roundoff at the already-validated equality.

## Examples and measured behavior

Defaults a=2, l₀=8, φ₀=30°. Signed b chooses winding; examples use positive b:

| Example | J/a | Outcome before leaving displayed domain | Minimum l | Time within abs(l)<a | Angular travel |
|---|---:|---|---:|---:|---:|
| Crossing | 0.65 | Reaches l < -12, no radial velocity reversal | crosses zero | 4.9125 | 2.06404 rad |
| Deflection | 1.4 | Returns to l > +12 | 1.95959184 | 1.1375 | 3.14236 rad |
| Near-critical | 1.0001 | Winds near throat, returns to l > +12 | 0.02828498 | 20.7125 | 10.8770 rad |

The near-critical offset is deliberately above critical by 1e-4, not the exact unstable
threshold. Analytic minima are about 1.95959179 and 0.02828498 respectively; tests require
sampled minima within 1e-5. Residence counts fixed samples over the displayed traversal;
it is not a wall-clock or performance measurement. Free edits within 1e-6 of critical show a
roundoff-sensitivity note; valid values are not snapped away from the threshold.

## Integration, boundaries and presentation

- `WorkspaceCore/EllisWormhole.swift`: CPU Double four-stage RK4 for (l,φ,l',φ'), fixed
  Δs=1/240. Only φ wraps after a full step; l has no sign switch, reset or discontinuity at zero.
  There is no energy/velocity renormalization, random recovery, steering or physical time dilation.
- Supported UI: a=1…4, l₀=-10…10, φ₀=0…360°, b=-2…2 subject to unit-speed admissibility.
  Keep numerical denominators nonsingular through a≥1. Non-finite state, |l|≥1e6 or >1% energy
  error stops with an explicit error. Tests use much tighter drift tolerances, below.
- Reference integration is independent of display extent and tested to s=1000. The finite mesh
  displays |l|≤12 by default. Playback pauses after its first full step reaching/exceeding that
  limit; it retains the real state (overshoot ≤one step), without a fabricated boundary clamp
  or reflection. Inspector and always-visible scene caption explain the pause; Restart resumes
  from initial data. The mathematical geometry continues beyond the mesh.
- Existing fixed clock clamps wall gaps at 0.25 s, bounds work to 64 steps/draw, drops excess
  simulation time and reports it. Playback rate 0.125×…4× (default 2×) changes due steps only.
  Pause consumes no affine distance; a paused single step advances exactly 1/240.
- Running presentation interpolates l and shortest angular displacement between the last two
  states using clock remainder, then re-embeds. It lags the solver by at most one step. Pausing/
  stepping displays the exact solver state, so a sub-step visual correction can occur. Particle
  centers stay on the analytic surface; polyline trail segments approximate arcs between samples.
  Particle and following camera use the **same** presentation point. Camera orientation remains
  user-controlled through crossing/turning; no normal-driven rotation or wall-time smoothing lag.
- Follow toggle exits without a target jump; Camera/⌘0 and Restore Defaults disable following.
  Very close views can intersect the surface; no camera collision system is claimed.

## Inspector and presentation modes

Native controls use the existing scrollable floating panel and numeric fields. Dragging,
resizing, snapping, keyboard movement and saved placement helpers are untouched.

- Launch example picker, actual threshold classification, throat radius, initial l/φ and b.
  J/a uses 12 significant display digits so values such as 1.000001 do not display as 1; other
  established controls retain six-digit formatting. Invalid commits and coupled-invalid launches
  remain visible/correctable, with playback paused.
- Playback rate, Pause/Resume, Step, Restart, Camera/⌘0, Follow, Restore Defaults.
- **Surface**: restrained nearest-sheet shading, optional mesh overlay. **Wireframe**: hidden-line
  parameter grid. **Trajectories**: no surface/depth occluder. These do not change the equations.
- Surface opacity is premultiplied **nearest-sheet coverage**, using a depth prepass to avoid
  order-dependent accumulation. It is not sorted multi-layer transmission. Rear trajectories
  remain depth-occluded while the sheet is shown; zero opacity or Trajectories reveals all paths.
  This deliberate transparency limitation is stated in the control help and needs visual review.
- Optional l=0 reference circle and existing coordinate grid. Particle/trajectory visibility,
  particle size, bounded history 256…8192 samples, fade delay/duration in affine units. Default
  trail retains ~34.13 units, fading after 20 over 12. Pause freezes age. Initial-condition,
  throat and history-size edits restart; presentation/rate/visibility/fade edits do not.
- Dedicated first-class gallery study uses the actual Ellis mesh plus twelve real integrated
  units, paused. Opening starts at s=0. The accepted static M2 Wormhole remains separately available.

## Architecture and resource reuse

New files: `WorkspaceCore/EllisWormhole.swift`, `CreativeMath/SurfaceMotionSession.swift`,
`WormholeSession.swift`, `WormholeInspector.swift`, `Tests/WorkspaceCoreTests/WormholeTests.swift`,
`Tests/LorenzMetalTests/WormholeRenderingTests.swift`. SwiftPM discovers them in existing targets;
Xcode memberships were added and statically checked. No dependency or rendering framework.

The narrow SurfaceMotionSession interface shares viewport/transport with Torus through thin
adapters; concrete solvers remain independent. Existing Torus defaults, clock, follow policy,
controls and results stay intact. Its M2 opaque surface path still uses one pass and the prior
material. Lorenz is not routed through this interface. Native menu commands use the active motion.

`SurfaceMesh(ellis:)` samples uniform w=asinh(l/a), giving uniform embedded height and adequate
neck resolution without excessive tessellation. Default 192×128 cells: 24,897 vertices (48 bytes),
49,152 triangles, 147,456 UInt32 indices. Geometry cache key distinguishes Ellis from M2 models.
Radii/extent changes upload immutable replacement buffers; animation/camera/material/mode changes
reuse them. Geometry is not built while wholly hidden until it is needed. Alpha/depth-only
pipelines are lazy; M2 viewports do not create/use them. Nearest-depth and coverage passes share
an encoder, then existing overlay depth is explicitly stored/loaded. Throat geometry is cached
by a and uses the existing line-quad pipeline.

The shared trail renderer gains optional visibility/head overrides and a depth tolerance uniform.
Torus defaults remain 0.005; Ellis uses 0.01 world units to resolve analytic paths against its
faceted mesh. This changes raster depth only, not trajectory coordinates. Three persistent upload
slots rotate under the same three-in-flight limit/serial queue; no per-frame buffer allocation,
readback or GPU wait. Coordinate-label snapshots retain the previous isolated observation path.

Source-derived capacities per viewport (not measured process memory):

- Mesh: 1,195,056 vertex bytes + 589,824 index bytes = 1,784,880 bytes.
- Throat circle: 8192 bytes; optional coordinate buffer ≤27,840 bytes.
- CPU ring: ≤131,072 bytes; three GPU uploads: 393,216 bytes.
- Default translucent view: two surface draws, one reference draw, trail and marker (five);
  coordinates add one. Opaque view reduces surface work to one draw; hidden mode skips it.

These exclude attachments, pipelines, UI, transient rebuild arrays and retained in-flight
resources. Actual frame times, CPU/GPU overhead, process memory and thermal behavior are
**NOT MEASURED**; no target FPS or memory-compliance claim is made.
