User requested the original triangle as the app logo, faster motion, a clearer particle and
better inspection. M3.1 remains unaccepted pending actual animation review.

## Changes

- `Assets/TriangleLogo.svg` and `AppIcon.svg`: vector version of the original Triangle Study's
  proportions and cool blue on the existing dark surface token. No image generation or new
  decorative styling. `AppIcon.iconset` contains native/Retina PNG sizes; `AppIcon.icns` is
  packaged in both the Xcode app and `scripts/build-app.sh` bundle with CFBundleIconFile.
- `scripts/generate-app-icon.swift` reproducibly renders the vectors using Core Graphics and
  packages PNG-backed ICNS chunks. Native NSImage decoding succeeds. System iconutil rejected
  the complete valid-size iconset in this restricted session, so the script writes the standard
  ICNS container directly and validates it. The actual 1024 PNG was visually inspected.
- Geodesic **Playback (×)**: live 0.125×…4×, default 2×. This changes how many unchanged
  1/240-second steps are due, without restarting or changing physical launch speed. The
  existing **Speed** control remains 0.25…8 world units per simulation second and restarts
  initial conditions. Their combined maximum is 32 world units per wall second, subject to
  the documented catch-up/drop policy. Single-step always advances one dt regardless of rate.
- **Particle size (pt)**: default diameter 12 screen points, adjustable 4…28. Retina conversion
  happens in the viewport; the marker no longer depends on a tiny fixed physical-pixel radius.
  **Trail width (pt)**: default 1.2, adjustable 0.5…3. Appearance edits keep the computed path.
- **Focus particle** centers the camera on the current sample, approaches from the outward
  surface normal, and chooses a safe local distance based on hole clearance. Pause first to
  inspect a point; this is a one-time focus, not an automatic following camera. Geodesic zoom
  now reaches distance 1; existing Lorenz/static-surface minimum 35 is unchanged. Camera reset
  restores the full torus. Shared camera projection adds an optional target, default origin.
- Gallery heading now explicitly names **Wormhole and Torus** and offers both entry buttons,
  while retaining the selected surface preview and existing `openSurface` accessibility ID.
  The Wormhole implementation currently remains the accepted static M2 surface. The prior
  M3.1 instruction explicitly excluded M3.2 Wormhole particle motion; clarification is pending
  whether the new request means missing static entry or authorization to start particle motion.

Close-focus depth handling uses a 0.005-world-unit tolerance mapped into perspective depth,
plus one raster depth unit. This is intended to resolve analytic samples against the fixed 192×96 faceted
mesh even at close range; a fixed depth-buffer bias alone changes its world-space tolerance
with camera distance. Mathematical positions are unchanged. Added a device-gated inner-equator
focus test between mesh columns. This tolerance is far smaller than the supported tube/hole
clearances; genuine rear occlusion is still depth-tested. GPU verification remains pending.

No new geodesic model, hidden steering, larger RK4 timestep, x-ray particle or Wormhole motion
was introduced. Surface depth relationships remain intact and require desktop verification.
