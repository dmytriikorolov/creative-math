## Implementation

- Lorenz equations: x′ = σ(y−x), y′ = x(ρ−z)−y, z′ = xy−βz. Defaults 10, 28, 8/3.
  State and time are dimensionless. CPU reference is Double; GPU integration/history are Float32.
- Classical RK4, nominal dt = 1/240, rounded to Float32 for Metal. Display callbacks only decide
  how many fixed steps to encode; rendering does not set dt. Tests exercise 30/60/120/144 Hz.
- Fixed clock: max wall gap 0.25 s, max 64 catch-up steps, speed 0.125–4. Excess time is dropped,
  never replaced by larger dt or lower precision. Pause resets the wall-time anchor; observed
  missing/minimized drawables reset it too. Other unobserved gaps use bounded catch-up/drop.
- Seed 0x4C4F5245. Integer hashing creates independent initial points in [0.98,1.02)³ around
  (1,1,1). Each GPU thread advances one trajectory and writes only its own history ring.
- Reset initializes the seed and executes 2400 + trailLength − 1 actual fixed steps. The first
  visible history spans t=10 through t=10+(trailLength−1)/240. This deterministic pre-roll
  creates an immediately inspectable scene. It is not a prerecorded trajectory or texture.
- Model edits retain current positions and clear history; count/history changes restart seeded
  pre-roll. When paused, model edits leave only the current point until Step/Resume; Reset
  rebuilds the full trail using the new parameters. Reset retains parameters, speed and pause.
  Preset selection restores its parameters/count/history/style/camera and speed 1, retaining pause.
- Input domain: σ 1–30, ρ 0–60, β 0.1–10; counts 1–128; history 256–8192 points. Numeric text
  requires Enter/focus loss to commit; Escape reverts. Invalid/non-finite values are rejected;
  count/history fields require integers. Topology sliders commit on release.
- Non-finite or |coordinate| ≥ 10000 states restart that trajectory and invalidate its old history,
  preventing a connecting segment across the restart. GPU tests inject NaN and inspect recovery
  when a device exists. Restart counters are read only by validation, not every app frame.

## Boundaries and resource ownership

`WorkspaceCore` contains pure math/reference, fixed clock, configuration, presets and camera data.
`LorenzMetal` owns one command queue, compute/render pipelines and private state/history buffers.
SwiftUI owns controls; the viewport owns its renderer/camera/clock. The inspector's mouse,
resize, snap, clamping and preference code is reused. No generic visualization engine, scene
file format, export, timeline or Optimization Lab was added.

Each state is float4 + uint4 (32 bytes); each history point is float4 (16 bytes). Default history
is 12×2048×16 = 393216 bytes (0.375 MiB); maximum is 16 MiB per renderer. Actual process/driver
memory is NOT MEASURED. Drawable textures, pipeline resources and overlapping in-flight buffer
replacement add memory; the 16 MiB figure is only history capacity, not total memory use.

Buffers are allocated at creation or count/length edits; model edits, reset, camera motion and
ordinary frames reuse them. One queue orders compute → ribbon rendering. Buffer memory barriers
separate compute dispatches. Three in-flight submissions bound queue growth. Per-frame command
buffers/encoders and small encoded uniform bytes are standard Metal submission objects; there
are no per-frame `makeBuffer` calls or trajectory readbacks in the app. Validation-only readback
uses staging and waits outside the render loop. Pre-roll dispatches are limited to 256 RK4 steps.

## Art direction and camera

These are implemented starting points, **not visually signed-off presets**:

| Preset | Trajectories | History | Width, physical px | Opacity | Direction |
|---|---:|---:|---:|---:|---|
| Classic | 12 | 2048 | 0.85 | 0.44 | Cool mineral/ivory; readable double scroll |
| Filament | 24 | 3072 | 0.55 | 0.25 | Fine teal/pearl strands; longer layered histories |
| Sculpture | 6 | 4096 | 1.25 | 0.65 | Copper; long paths and an oblique camera |

Presets are typed data (configuration, camera, width/opacity and linear-RGB endpoints), not
renderer-specific branches. Rendering uses six generated vertices per segment, screen-space
ribbons, analytic edge feathering, height-based color, age fade and restrained depth attenuation.
There is no point cloud, bloom, post-processing or decorative animation. Blending is premultiplied
alpha in an sRGB drawable, with linear color/clear values. No depth attachment: trails are
translucent; this is not opaque-surface hidden-line rendering.

Math coordinates (x,y,z) map to display (x,z−25,−y), preserving a right-handed basis with Y up.
Camera uses a right-handed view and Metal 0–1 depth perspective. Orbit pitch is bounded to
±1.35 rad; distance 35–250; pan ±100 world units. Camera state does not enter integration.

Controls: drag orbit; Shift/Option-, right- or middle-drag pan; scroll/pinch zoom. Focused canvas
arrows orbit and +/− zoom. Space toggles pause; ⌘] steps while paused; ⌘R resets simulation;
⌘0 resets camera. Panel arrows still move the inspector when its header is focused.

## Reproducibility limits

The seed hash and step sequence are fixed; each trajectory has independent memory, with no
cross-thread floating-point reductions. Safe Metal math is requested (fast math disabled on
macOS 14). Same-device/pipeline reset and dispatch-batching equality are tested when GPU access
exists. They have NOT been verified here. Float32 rounding, FMA contraction, GPU architecture,
compiler, driver and OS changes can alter results. Lorenz chaos amplifies short-horizon roundoff;
long-horizon bit identity across architectures is not promised. Live UI event timing is also not
an offline deterministic input timeline. Reference tolerance applies only to the tested horizon.
