# M3.2 follow across relaunches — 2026-11-04

User requested preserving Follow selected ball across disappearance/relaunch, holding
camera position while waiting, showing waiting status, smoothly returning on relaunch,
and immediately following another selected active ball.

## Implemented

Removed WormholeSession's automatic follow disable on disappearance/generation change.
Added a pure RelaunchCameraTracking policy in the existing CameraProjection.swift:

- Keep follow intent with absent targets and hold the last resolved target.
- Show “Waiting for selected ball to relaunch” in the inspector. Follow can also be
  enabled while a slot is waiting. On reacquisition show “Returning to selected ball”.
- Cubic easing over 0.6 wall-clock seconds toward the current moving particle; bounded
  per-draw elapsed time. This affects the camera only, not integration or launch timing.
- Selecting another active ball follows immediately; selecting a waiting slot holds.
- Reduce Motion skips animated reacquisition; paused redraws contribute zero elapsed.
- Disabling follow freezes the current target. Camera reset/defaults disable it.
- Preserve orbit, zoom and user pan. Keep per-frame target state observation-ignored;
  publish only changes in follow enabled/status. Existing Torus follow is unchanged.
